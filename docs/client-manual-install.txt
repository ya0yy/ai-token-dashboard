AI Token Dashboard：纯 Node 手动采集与公网 HTTPS 上报

需要 Node.js 22.15以上，在保存本机AI日志的同一用户下操作。
不需要SSH密钥、隧道或网页构建，也不需要运行Python来执行手动采集。

解压与配置
将 ai-token-client-manual.tar.gz 传到目标机器，在同一终端执行：
umask 077
AI_TOKEN_DIR="$HOME/.local/share/ai-token-dashboard"
mkdir -p "$AI_TOKEN_DIR"
tar -xzf ai-token-client-manual.tar.gz --strip-components=1 -C "$AI_TOKEN_DIR"
cd "$AI_TOKEN_DIR"

创建client.json，填写不同设备名和真实采集令牌：
{
  "device": "mac-home",
  "ingestToken": "填写真实INGEST_TOKEN",
  "pushUrl": "https://tks.420114.xyz/api/ingest",
  "timezone": "Asia/Shanghai"
}
chmod 600 client.json
Linux的设备名可改为linux-dev，每台设备必须唯一。

手动执行
node "$AI_TOKEN_DIR/collect-once.mjs"
采集封装每轮限时15分钟，直接通过公网HTTPS上报。
在维护源码仓库里，手动入口为 collector-entry-manual.mjs，运行封装为 collect-once.mjs。
在手动分发包里，入口使用 collector-entry.mjs，封装已适配对应名称。

原生命令
在项目根目录执行：
npm run collect -- --device mac-home --push https://tks.420114.xyz/api/ingest --token "填写真实INGEST_TOKEN"
原生命令执行一次后退出；配置中device和pushUrl要保持稳定。

自动定时
当前自动安装方式统一为crontab，详见 client-python-install.txt。
自动安装器会生成带互斥锁、超时和日志的cron任务。
若自行给原生命令或纯Node入口配置crontab，需要自行保证超时与互斥，并使用Node绝对路径。
不要同时保留同一设备的多套调度任务。
切换公网地址首次可能重传已有历史，服务端按主键更新，不会把重传的用量直接累加。
